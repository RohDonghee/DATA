# 1. Classification I  
*(Fundamentals of Classification)*  

---

## 1.1 What is Classification?

- **Goal**
  - Learn a mapping from input features **X** to a **categorical label Y**.
  - For a new, unseen data point, predict:
    - Either a **class label** (e.g., “spam”, “not spam”), or  
    - A **probability** for each class, e.g. \(P(Y = \text{spam} \mid X)\).

- **Input / Output Form**
  - Input: **feature vector** \(X = (x_1, x_2, \dots, x_p)\), where each \(x_i\) is a measured attribute.
  - Output:
    - \(\hat{y}\): predicted class label, or  
    - \(\hat{p}_k = P(Y = k \mid X)\): probability that X belongs to class k.

- **Typical Applications**
  - Spam detection, credit default prediction, disease diagnosis, image recognition, sentiment analysis, etc.
  - Whenever the answer is a **category**, not a continuous number, we are in a classification setting.

---

## 1.2 Types of Classification

### 1.2.1 Binary Classification

- **Definition**
  - Only **two possible classes**, often referred to as:
    - Positive vs Negative (e.g., fraud / non-fraud),
    - Class 1 vs Class 0,
    - Yes vs No.
- **Examples**
  - Fraud detection: fraud / no fraud.
  - Medical test: disease / no disease.
  - Churn prediction: will churn / will not churn.

---

### 1.2.2 Multi-class Classification

- **Definition**
  - **More than two** mutually exclusive classes.
- **Examples**
  - Handwritten digit recognition: digits 0–9 (10 classes).
  - Document topic classification: sports / politics / technology / entertainment.
- **Note**
  - Many binary techniques can be extended to multi-class (e.g., One-vs-Rest, softmax regression).

---

### 1.2.3 Ordered (Ordinal) Classification

- **Definition**
  - Classes have a **natural order**, but the “distance” between them is not numeric.
- **Examples**
  - Customer satisfaction: very low < low < medium < high < very high.
  - Credit ratings: AAA > AA > A > BBB > … .
- **Modeling**
  - Need to respect ordering (e.g., misclassifying “low” as “medium” is less serious than “low” as “very high”).

---

## 1.3 General Classification Framework

- **Mathematical View**
  - We want to learn a function:
    - \(f: X \rightarrow Y\) or  
    - \(f: X \rightarrow P(Y \mid X)\)
  - such that predictions on **new data** are as accurate as possible.

- **Training Procedure**
  - Given a labeled dataset \(\{(x_i, y_i)\}_{i=1}^n\),
    - Choose a model family (e.g., logistic regression, decision tree),
    - Fit model parameters to minimize some loss (e.g., classification error, cross-entropy).

- **Probabilistic Interpretation**
  - Many classifiers aim to approximate **posterior probabilities** \(P(Y = k \mid X)\) and then pick:
    - \(\hat{y} = \arg\max_k P(Y = k \mid X)\).

---

## 1.4 Training vs Testing (and Validation)

- **Training Set**
  - Used to **fit** model parameters.
  - The model “sees” these examples and adapts to them.

- **Validation Set**
  - Used to **tune hyperparameters** (e.g., tree depth, regularization strength).
  - Helps choose between different models without touching the test set.

- **Test Set**
  - Completely held-out data used to estimate **generalization performance**.
  - Must not be used during training or model selection to avoid “cheating”.

- **Data Leakage**
  - Occurs when information from the test set (or future data) leaks into training.
  - Leads to over-optimistic performance estimates and poor real-world performance.

---

## 1.5 Decision Boundary

- **Concept**
  - The set of points in feature space where the model is **“undecided”** between classes.
  - For binary classification:
    - Usually defined by the points where \(P(Y=1 \mid X) = 0.5\),  
      or where the model gives equal score to both classes.

- **Shape Depends on Model**
  - Linear models (e.g., logistic regression) → **linear** decision boundary (line, plane, hyperplane).
  - Decision trees → **piecewise-constant** regions with axis-aligned splits.
  - Kernel SVMs, neural networks → potentially **highly nonlinear** boundaries.

- **Interpretation**
  - Points **on one side** of the boundary are labeled as class A,
  - Points **on the other side** are labeled as class B.

---

## 1.6 Overfitting vs Underfitting

### 1.6.1 Overfitting

- **Definition**
  - Model is **too complex** relative to the amount of data and noise level.
  - It memorizes the training data, including random fluctuations/noise.

- **Symptoms**
  - Very low training error.
  - Much higher test error (poor performance on new data).
  - Decision boundary looks extremely jagged or “wiggly”.

- **Causes / Examples**
  - Too many parameters, very deep trees, overly complex neural networks.
  - Not enough regularization, not enough data.

---

### 1.6.2 Underfitting

- **Definition**
  - Model is **too simple** to capture the true pattern in the data.

- **Symptoms**
  - High training error and high test error.
  - Model predictions are close to a naive baseline (e.g., always predicting majority class).

- **Causes / Examples**
  - Using a linear model for a highly nonlinear relationship.
  - Overly strong regularization (forcing coefficients to be near zero).

---

### 1.6.3 Goal: Balance Between the Two

- **Bias–Variance Trade-off**
  - Underfitting → high bias, low variance.
  - Overfitting → low bias, high variance.
- **Practical Approach**
  - Use validation / cross-validation to pick a model complexity that minimizes **test (generalization) error**.

---

# 2. Classification II  
*(Logistic Regression, Bayes Theorem, Naïve Bayes)*  

---

## 2.1 Probability Foundations

### 2.1.1 Independent Events

- **Definition**
  - Events A and B are independent if:
    - \(P(A \text{ and } B) = P(A) \cdot P(B)\).
  - Knowing that A occurred gives **no information** about B.

- **Example**
  - Rolling two fair dice:
    - Result of die 1 is independent of result of die 2.

---

### 2.1.2 Dependent Events

- **Definition**
  - Events A and B are dependent if:
    - \(P(A \text{ and } B) \neq P(A) \cdot P(B)\).
  - Occurrence of one event **changes the probability** of the other.

- **Example**
  - Height and gender:
    - Probability of being “tall” is different for males and females.
    - So “tall” and “female” are dependent events.

---

### 2.1.3 Conditional Probability

- **Definition**
  - Probability of event A **given** that event B has occurred:
    - \(P(A \mid B) = \dfrac{P(A \cap B)}{P(B)}\).

- **Intuition**
  - Restrict the sample space to B (only consider cases where B happened),
  - Then ask: among those, what fraction also have A?

---

### 2.1.4 Bayes Theorem

- **Formula**
  - \(P(A \mid B) = \dfrac{P(B \mid A) \cdot P(A)}{P(B)}\).

- **Terminology**
  - **Prior** \(P(A)\): belief about A before seeing B.
  - **Likelihood** \(P(B \mid A)\): how likely we are to see B if A is true.
  - **Evidence** \(P(B)\): overall probability of B.
  - **Posterior** \(P(A \mid B)\): belief about A **after** observing B.

- **In Machine Learning**
  - A = “Y = k” (a class / hypothesis),
  - B = observed features X,
  - We use Bayes theorem to compute \(P(Y = k \mid X)\).

---

## 2.2 Logistic Regression

### 2.2.1 Purpose

- **What It Does**
  - Models the probability of a **binary outcome** as a function of features.
  - Ensures predicted values are in **[0, 1]**.

- **Why Not Linear Regression?**
  - Linear regression can produce values < 0 or > 1, which are invalid probabilities.
  - Logistic regression uses a **sigmoid link** to map real numbers to (0, 1).

---

### 2.2.2 The Logistic Model

- **Log-odds (Logit) Form**
  - \[
    \log\frac{p}{1 - p} = \beta_0 + \beta_1 X
    \]
  - Left-hand side: log-odds of the positive class.

- **Sigmoid Function**
  - Let \(z = \beta_0 + \beta_1 X\),
  - Then:
    \[
      p = P(Y = 1 \mid X) = \frac{1}{1 + e^{-z}}
    \]
  - As z → +∞, p → 1; as z → −∞, p → 0.

- **Interpretation**
  - When X increases by 1 unit, the log-odds change by \(\beta_1\).
  - If \(\beta_1 > 0\): larger X → higher probability of positive class.
  - If \(\beta_1 < 0\): larger X → lower probability of positive class.

---

### 2.2.3 Multivariable Logistic Regression

- **Model**
  - \[
    \log\frac{p}{1 - p} = \beta_0 + \beta_1 x_1 + \dots + \beta_p x_p
    \]
  - Each feature \(x_j\) has its own coefficient \(\beta_j\).

- **Interpretation**
  - \(\beta_j\): effect of \(x_j\) on log-odds, **holding other variables constant**.
  - Odds ratio for a 1-unit increase in \(x_j\): \(e^{\beta_j}\).
    - If \(e^{\beta_j} = 2\): odds double for each 1-unit increase in \(x_j\).

---

### 2.2.4 Coefficient Significance

- **Hypothesis Testing**
  - Null hypothesis: \(H_0: \beta_j = 0\) (feature has no effect).
  - Use standard errors and z-statistics to test if \(\beta_j\) is significantly different from 0.

- **p-values**
  - Small p-value (e.g., < 0.05) suggests that the corresponding feature is a **useful predictor**.
  - Large p-value suggests the feature may not contribute much to the model.

---

## 2.3 Naïve Bayes Classifier

### 2.3.1 Core Idea

- **Use Bayes Theorem for Classification**
  - We want:
    \[
      P(Y = y \mid X) \propto P(Y = y) \cdot P(X \mid Y = y)
    \]
- **Naïve Independence Assumption**
  - Features are **conditionally independent** given the class:
    \[
      P(X_1, \dots, X_p \mid Y) = \prod_{i=1}^{p} P(X_i \mid Y)
    \]
  - This is rarely perfectly true, but greatly simplifies estimation.

---

### 2.3.2 Naïve Bayes Formula

- **Posterior Probability**
  - \[
      P(Y = y \mid X) \propto P(Y = y)\, \prod_{i=1}^{p} P(X_i \mid Y = y)
    \]
- **Decision Rule**
  - Predict the class y that **maximizes** this posterior:
    - \(\hat{y} = \arg\max_y P(Y = y \mid X)\).

---

### 2.3.3 Estimating the Components

- **Class Prior \(P(Y = y)\)**
  - Estimated from the **relative frequency** of each class in the training data.

- **Categorical Features**
  - For each class y and each category c of feature \(X_i\):
    - \(P(X_i = c \mid Y = y) = \dfrac{\#(X_i = c, Y = y)}{\#(Y = y)}\).

- **Continuous Features**
  - Often assume a **Gaussian distribution** for each class:
    - Estimate mean and variance of \(X_i\) within each class y.
    - Use the normal density to compute \(P(X_i \mid Y = y)\).

- **Smoothing**
  - Use techniques like Laplace smoothing to avoid zero probabilities when some category never appears in training.

---

### 2.3.4 Advantages and Limitations

- **Advantages**
  - Very fast training and prediction.
  - Works well with high-dimensional data (e.g., text classification).
  - Requires relatively small amounts of data.

- **Limitations**
  - Independence assumption is often violated.
  - When features are strongly correlated, performance can degrade.

---

# 3. Classification III  
*(Model Evaluation, Confusion Matrix, ROC, AUC)*  

---

## 3.1 Why We Need Evaluation Metrics

- **Not All Classifiers Are Equal**
  - Different models can give very different performance on the same dataset.

- **Accuracy is Sometimes Misleading**
  - In **imbalanced** problems (rare positives), predicting all negatives can still have high accuracy but be useless.
  - Example: 1% fraud rate → predicting “no fraud” for everyone gives 99% accuracy but finds **zero** fraud cases.

- **Conclusion**
  - We need **richer metrics** to understand the behavior of a classifier: Precision, Recall, F1, ROC, AUC, etc.

---

## 3.2 Confusion Matrix

- **Binary Classification Confusion Matrix**

| Actual / Predicted | Positive (Yes) | Negative (No) |
|--------------------|----------------|---------------|
| **Actual Positive**| TP             | FN            |
| **Actual Negative**| FP             | TN            |

- **Definitions**
  - **TP (True Positive)**: Correctly predicted positive.
  - **TN (True Negative)**: Correctly predicted negative.
  - **FP (False Positive)**: Predicted positive but actually negative.
  - **FN (False Negative)**: Predicted negative but actually positive.

---

## 3.3 Common Metrics

### 3.3.1 Accuracy

- **Formula**
  - \[
    \text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}
    \]

- **Interpretation**
  - Overall fraction of correctly classified instances.

- **Caution**
  - Does not reflect **class imbalance** or different costs of FP vs FN.

---

### 3.3.2 Precision

- **Formula**
  - \[
    \text{Precision} = \frac{TP}{TP + FP}
    \]

- **Interpretation**
  - Among all instances **predicted positive**, how many are actually positive?
  - High precision → few false alarms.

---

### 3.3.3 Recall (Sensitivity, True Positive Rate, TPR)

- **Formula**
  - \[
    \text{Recall} = \frac{TP}{TP + FN}
    \]

- **Interpretation**
  - Among all **actual positives**, how many does the model catch?
  - High recall → model rarely misses positives.

---

### 3.3.4 Specificity (True Negative Rate, TNR)

- **Formula**
  - \[
    \text{Specificity} = \frac{TN}{TN + FP}
    \]

- **Interpretation**
  - Among all **actual negatives**, how many are correctly predicted as negative?
  - High specificity → few false positives.

---

### 3.3.5 F1 Score

- **Formula**
  - \[
    F1 = 2 \cdot \frac{\text{Precision} \cdot \text{Recall}}{\text{Precision} + \text{Recall}}
    \]

- **Interpretation**
  - Harmonic mean of Precision and Recall.
  - Punishes models that have **very high precision but very low recall**, or vice versa.
  - Useful when you want a single metric balancing both.

---

## 3.4 Class Imbalance Issue

- **Definition**
  - One class (usually negative) is much more frequent than the other (positive).

- **Examples**
  - Fraud detection: fraud cases << non-fraud.
  - Medical screening: diseased patients << healthy.
  - Defect detection: defective items << normal items.

- **Problems with Accuracy**
  - A trivial classifier that always predicts the majority class can achieve high accuracy but be useless.

- **Better Metrics**
  - Focus on **Recall**, **Precision**, **F1 score**, and **ROC/AUC**.
  - Sometimes use **balanced accuracy** or other specialized metrics.

---

## 3.5 Cutoff Thresholds

- **Continuous Score vs Hard Label**
  - Many classifiers output a **probability** or **score** \(s(X)\) rather than a hard label.
  - We choose a threshold \(t\):
    - If \(s(X) \geq t\) → predict positive,
    - Else → predict negative.

- **Effect of Changing Threshold**
  - Lower threshold:
    - More positives predicted → Recall (TPR) ↑, but FPR ↑ as well.
  - Higher threshold:
    - Fewer positives predicted → FPR ↓, but Recall (TPR) ↓.

- **Key Idea**
  - Threshold determines the trade-off between **detecting positives** and **avoiding false alarms**.

---

## 3.6 ROC Curve (Receiver Operating Characteristic)

- **Definition**
  - A plot of **TPR** (Recall) vs **FPR** for all possible threshold values.

- **Axes**
  - x-axis: False Positive Rate \(= \frac{FP}{FP + TN}\).
  - y-axis: True Positive Rate \(= \frac{TP}{TP + FN}\).

- **Interpretation**
  - A curve **closer to the top-left corner (0,1)** indicates better performance.
  - A **random classifier** corresponds to the diagonal line from (0,0) to (1,1).

- **Usage**
  - Compare different models’ ROC curves to see which one dominates (higher TPR for same FPR).

---

## 3.7 AUC (Area Under the ROC Curve)

- **Definition**
  - The area under the ROC curve, denoted AUC.

- **Interpretation**
  - Probabilistic view:
    - AUC = probability that the classifier ranks a random positive sample **higher** than a random negative sample.
  - Range:
    - 1.0 = perfect classifier.
    - 0.5 = random guessing.

- **Advantages**
  - **Threshold-independent**: summarizes performance across all thresholds.
  - Good for comparing classifiers when you don’t yet know the appropriate threshold.

---

## 3.8 Asymmetric Misclassification Costs

- **Motivation**
  - In many real problems, **FN and FP do not have the same cost**.
  - Example:
    - Missing a fire (FN) is much worse than a false alarm (FP).
    - Missing a disease (FN) is much worse than sending a healthy person for extra tests (FP).

- **Implication**
  - You may want to:
    - Lower the threshold to **reduce FN** (increase Recall), accepting more FP.
    - Or tune a cost-sensitive loss function that directly penalizes FN more.

- **Examples**
  - Fraud detection:
    - FN → fraud goes undetected → financial loss.
    - FP → manual review of non-fraud → smaller operational cost.
  - Medical diagnosis:
    - FN → sick patient untreated.
    - FP → extra test and temporary anxiety.

- **Practical Strategy**
  - Choose a model and threshold that **optimizes expected cost or profit**, not just a generic metric like accuracy.
