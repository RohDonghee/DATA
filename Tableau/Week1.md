## 3강. 데이터연결과 데이터 유형

> **🧞‍♀️ 라이브와 추출의 차이가 무엇인가요? 어떤 경우 사용하나요?**

```
■ 라이브
 □ 장점
  - 원본 데이터에 직접 연결하여 작업 진행 
  - 최신 데이터 즉시 반영(원본이 업데이트 시, 바로 반영)
 □ 단점
  - 원본 DB 성능/네트워크에 따라 대시보드가 느려질 수 있음
  - 사용자 증가 시 DB에 쿼리 부하 발생

■ 추출 
 □ 장점
  - 다량에 데이터 작업 시 속도 빠름
  - 오프라인 작업 가능 
 □ 단점
  - 데이터 최신성이 ‘갱신 주기’에 의존 (1시간마다/매일 새벽 등)
```



## 4강. 데이터결합과 관계

> **🧞‍♀️ 어떤 경우에 관계를, 어떤 경우에 조인을 사용하나요?**

```
■ 관계(Relationship): 테이블을 미리 합치지 않고 “연결 규칙”만 정의하여 시트에서 쓰는 필드에 맞춰 동적으로 결합/집계
 - 논리 계층(Logic layer)
 - 테이블별 그레인(데이터 단위) 보존 
 - 시트마다 필요한 테이블만 묶여 쿼리 생성(유연함)

■ 조인(Join): 데이터 소스 단계에서 SQL처럼 미리 고정 결합(INNER/LEFT/RIGHT/FULL) → 결과 테이블 기준으로 분석
 - 물리 계층(Physical layer)
 - 결합 결과가 덩어리로 고정
 - 그레인 다르면 행 증가 → 합계/평균 등 중복 집계 위험 ↑
```



## 5강. 데이터결합과 조인

> **🧞‍♀️ 해당 목적 달성을 위해서 Sample store 데이터셋의 어떤 시트를 조인(혹은 릴레이션)해야 할까요? 조인키는 무엇인지, (inner, outer, left, right) 조인 유형은 무엇일지 논의해주세요.**

```
- Inner 조인: 데이터를 결합할 때, 두 테이블에서 모두 일치하는 항목만 포함시킴.
- Left/ Right 조인: 한쪽 테이블과 반대쪽 테이블과의 일치 항목 (일치 값이 없으면 NULL)
- Outer 조인: 두 테이블의 모든 값

※ JOIN은 같은 데이터 형식으로 결합 가
```

## 7강. 데이터 결합과 유니온

> **🧞‍♀️ 유니온을 사용하기 위한 전제 조건은 무엇인가요?**

```
■ 유의사항 
- 한 테이블의 행을 다른 테이블에 추가하여 결합하는 방식
- 유니온으로 결합하기 위해서 테이블 구조가 동일해야 함
- 각 테이블의 필드 수가 같고, 필드 이름과 데이터 유형이 일치해야 함
■ 방법
(1) 새 유니온 클릭 후, 유니온하고자 하는 테이블을 드래그 앤 드롭
(2) 테이블 하나를 필드로 끌어온 후에, 시트 테이블 및으로 드래그  
```


## 8강. 라이브와 추출

> **🧞‍♀️ 라이브와 추출 방법의 차이가 무엇인가요? 어떤 경우에 추출을 사용하면 좋을까요?**

```
■ 라이브
 □ 장점
  - 최신 데이터 즉시 반영(원본이 업데이트 시, 바로 반영)

■ 추출 
 □ 장점
  - 오프레미스 데이터 등을 최신화하기 위해서는 매번 새로고침 필요 
```

**참고자료 : 온프레미스 데이터란?**

기업이나 조직이 자체적으로 보유한 물리적 서버나 데이터 센터 내에서 직접 관리하는 데이터로, 조직 내의 하나 이상 서버에서 통제됩니다. 본 서버들은 기업의 데이터센터나 물리적 위치에 설치되어 있으며, 네트워크를 통해 해당 데이터에 접근하고 관리할 수 있습니다.



## 9강. 데이터형식

| 데이터 유형 | 한줄 설명/주로 쓰는 곳 |
|---|---|
| 텍스트(문자열) 값 | 이름, 카테고리, 코드처럼 “글자”로 처리 |
| 날짜 값 | 연/월/일 단위의 날짜(시간 없음) |
| 날짜 및 시간 값 | 타임스탬프(시간 포함: YYYY-MM-DD HH:MM:SS 등) |
| 숫자 값 | 합계/평균/비율 등 집계 가능한 수치 |
| 부울 값(관계형에만 해당) | True/False로 조건 필터링, 플래그 컬럼에 사용 |
| 지리적 값(맵에 사용) | 국가/시도/시군구/우편번호/위경도 등 지도 시각화용 |
