## 49강. 대시보드패널

```
- 하단 바에서 '대시 보드'를 선택
- 기존에 있던 시트를 대시보드 패로 불러와서 반응형으로 사용이 가능
```


## 50. 대시보드 구성방식
> **🧞‍♀️ 부동과 바둑판식 방식을 차이를 중점으로 기술해보세요**
```
■ 바둑판식
- 격자무늬 구조에 따라 개체 구성 가능
- 대시보드 크기를 변경해도, 개체가 유사한 형식을 유지할 수 있음
- 행/열 컨테이너(가로·세로) 기반으로 ‘칸’에 맞춰 배치되어 정렬이 쉽고, 간격·높이·너비를 일관되게 맞추기 좋음
- 반응형(화면 크기 변화) 대응이 비교적 안정적이라, 해상도/디바이스가 달라도 레이아웃 깨짐이 덜함
- 대시보드 표준 템플릿(헤더-필터-본문-풋터) 같은 구조화된 레이아웃에 특히 유리함

■ 부동식
- 개체를 자유롭게 배치할 수 있으며, Drag&Drop을 통해 활용 가능
- 개체를 움직이라더라도, 다른 개체에는 영향을 주지 않음
- 픽셀 단위로 위치를 정교하게 조정할 수 있어, 배너형 헤더·주석·강조 박스·이미지 오버레이 등 “디자인 연출”에 강함
- 대신 대시보드 크기/해상도 변화에 취약해서, 화면이 바뀌면 요소가 겹치거나 여백이 어색해질 수 있음
- 겹치기(레이어링) 표현이 쉬움: KPI 카드 위에 아이콘/설명 텍스트를 올리거나, 특정 영역에 강조 라벨을 얹는 방식에 유리함
```


## 51. 대시보드 컨테이너
```
- 가로 컨테이터 : 내부 컨테이너 수평 공간 배열
- 세로 컨테이너 : 내부 컨테이너 수직 공간 배열

- 구상하고 있는 컨테이너의 형태에 따라 컨테이너를 덧입혀가면서 내용을 시각화해서 표현

```


## 52. 레이아웃 패널
```
- 그래프의 제목은 워크시트의 이름과 동일하며, 숨길 수 있음
- 레이아웃 패널의 '계층 구조'를 확인하면 복잡하게 얽힌 컨테이너 구조를 한눈에 파악하고 수정하기에 용이
```

## 55. 대시보드 URL [동작 - URL로 이동]
```
- URL로 이동동작을 설정 가능
- URL '삽입'을 통해 지역 등을 설정함으로써, 하나의 URL이 중복해서 여러 지역으로 반영되지 않도록 할 수 있
- 웹 페이지 개체가 없는 경우 새 탭 / 웹 브라우저 개체 등을 선택하여 활용 가능 
```


## 56. 대시보드 시트에 이동 동작 [동작 -시트로 이동]
```
- 대시보드 하나로는 부족한 경우, 1개 이상의 대시보드를 활용하여 데이터 표현 가능
- 대시보드와 대시보드를 연결하여 표현 가능
- '동작-시트로 이동' 과 같이 '동작-필터'를 적용해야, 양방향으로 반영이 됨. (ex. 모든 국가에 대한 데이터가 아닌 클릭한 특정 국가만 표현)
- '요약 대시보드'에서 '상세 대시보드'로 넘어가는 드릴스루(Drill-through) 구조를 만들 때 필수적
```
